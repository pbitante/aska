# Changelog: aska

Each version's section is also its GitHub release notes (tag `aska-v<version>`). Print one with
`node scripts/release-notes.mjs aska <version>` from the repo root.

## 0.8.1 (unreleased)

A cheaper chair (#2).

**Changed**
- **Panelists read their own prompt and brief:** the panel skill saves each persona prompt to
  `<dir>/prompts/<name>.md` and gives each panelist only that path and the brief's. Before, the
  chair copied every prompt and the brief into each panelist call, and again into each re-ask:
  most of the chair's output tokens, which then stayed in its context for the rest of the run.
- **One name per panelist:** the prompt file, the judgment file and `check-judgment` all use the
  lineup row's `canonical` (`aska:tester`). Chairs used to pick a short or a canonical name.

**Fixes**
- **`compare` rejects a `model` with no `modelSource`** in `panel-result.json`. Before, such an
  entry was recorded and tagged in the report with no source.
- **Panel eval approver:** a Write through `..` after a folder that doesn't exist yet, such as
  `aska-panel-x/nope/../../file`, is now denied. `realpath` can't resolve such a path, and the
  folder check passed it while the Write landed outside.

## 0.8.0 (2026-10-13)

Pick the model each panelist runs on, and see it in the report (#3).

**New**
- **A persona's default model:** `model: haiku` (or another model alias such as `sonnet` or `opus`) in a persona's
  frontmatter runs its panelist on that model unless something more specific says otherwise.
  It's inherited through `extends`, shown by `explain`, listed by `list personas --json`, and
  settable with `patch`.
- **Per-run models:** `/aska:panel --model sonnet …` puts every panelist on one model, and
  `<persona>@<model>` puts one panelist on its own: `/aska:panel guardian tester@sonnet : …`.
  A saved panel takes tags for its members, `/aska:panel code tester@sonnet : …`, and still runs
  as that panel. Words work too ("tester on sonnet").
- **Precedence:** a panelist's own tag, then `--model`, then the saved panel's `models`, then the
  persona's `model`, then your session's model.
- **`persona lineup --json [--model <m>] <names…>`:** resolves a lineup into the panelists to
  launch and the model each runs on, with where it came from (`modelSource`). The panel skill
  uses it for every run.
- **Recorded models:** each `panel-result.json` entry records `model` and `modelSource`.
  `compare` passes them on, and `compare --json` adds `mixedModels`. The report tags each
  panelist's model whenever any ran on a named one, and tags the disagreements when the
  models differ. Kept runs' `meta.json` rows record `model` and `modelSource`.
- **The gate's model:** `/aska:gate … --model <m>`, or `model:` on your own `gate` persona.
  Opus is still the default.
- **Saving a lineup** keeps per-panelist models, and asks before saving a run-wide `--model`.

**Compatibility**
- Runs made before 0.8.0 compare and report exactly as before; they show no models.
- `compare --json` gains keys (`model` and `modelSource` on verdict rows, `mixedModels` at the
  end). No existing key changed.
- Persona lineups now record each panelist by its canonical name (`aska:guardian`, not
  `guardian`). A saved panel records each member as the panel lists it, and the panel by its
  canonical name (`aska:code`).
- A saved panel whose `models` uses `fable` needs aska 0.8.0 or later; earlier versions reject it.

**Known gap:** aska-editor reads runs that carry models but doesn't show the models yet.

## 0.7.2 (2026-10-12)

A patch release: kept runs can live somewhere else, and the git guard around them now covers
bare-repo dotfiles.

**Fixes**
- **Kept runs in a dotfiles home** (#5): `runs new` now refuses a run store that a bare dotfiles
  repository tracks (`git --git-dir=~/.dotfiles --work-tree=~`). It also refuses one inside
  `$GIT_WORK_TREE`, or inside `$GIT_DIR`'s `core.worktree`. Before, these weren't detected, so
  briefs and judgments could land in a tracked home directory. A bare repository with no index,
  such as a mirror or a backup clone, doesn't count.
- **Render marker** (#8): rendered agent files now say `# Generated by aska.` instead of the old
  project name. Files rendered by earlier versions are still recognised and updated as usual.

**New**
- **`ASKA_RUNS_DIR`:** keeps panel runs in a folder of your choice instead of
  `~/.claude/aska/runs/`. It must be an absolute path to a folder you own, otherwise `runs new` and
  `runs list` fail with the new `E_RUNS_DIR`. It's kept owner-only and checked by the same git
  guard.

**Known gap:** aska-editor still reads runs only from `~/.claude/aska/runs/`, so it won't show runs
kept under `ASKA_RUNS_DIR` yet.

## 0.7.1 (2026-10-12)

The first public release of **aska**: swappable reviewer personas for Claude Code.

- **Skills:**
  - `/aska:panel`: runs 2–6 personas as parallel, read-only panelists, compares their judgments,
    and reports their disagreements and follow-ups;
  - `/aska:author`: writes or tunes a persona or unit;
  - `/aska:operator`: validates, explains and renders them;
  - `/aska:gate`: scores a step's adversarial gate as pass, pass with conditions, or fail.
- **Starters:** units, personas (guardian, tester, maintainer, red-team, historian, planner,
  accelerator, trimmer and more), and saved panels such as `aska:code`, `aska:code-lean`,
  `aska:plan` and `aska:ship`.
- **Code panels:**
  - they run the project's own checks first, in a throwaway worktree;
  - they list every tracked file in the materials;
  - an investigator agent gathers evidence for follow-ups.
- **Models:** per-panelist model choice in saved panel files (`haiku`, `sonnet` or `opus`).
- **Kept runs:** panel runs are kept under `~/.claude/aska/runs/`, owner-only.
